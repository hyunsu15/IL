해당내용은 mybatis-spring의 현버전에 있는 tooManyResultException을 스프링표준 예외로 바꾸는 작업을 하고있음.
스프링 마이바티스도 이해가 안되는게, 스프링에서 추상화단계를 만들어줬지만, 자기만의 체계를 쓴다. 
해당 작업을 안하면 정확하게 잡을려면 MyBatisSystemException에서 e.getCause() instanceof TooManyResultException 으로 꾸준히 잡아야한다.

## 우선 생각나는 방법은 3가지가 있다.
- aop 
- 빈후처리기
- 예외번역기 교체

더 많은 방법이 있을 수 있지만, 우선 고려한 것은 이 3가지다. 우선 aop는 스프링-aop 라이브러리를 설치해야 편하기에, 해당 방법은 우선 만들지 않고, 나머지 내용들을 구성하겠다. 어차피 내용은 비슷하다.

## 빈후처리기 방식
```
@Component
public class MapperExceptionNormalizer implements BeanPostProcessor {

    @Override
    public Object postProcessAfterInitialization(Object bean, String beanName) {
        // 매퍼 빈만 선별: 인터페이스에 @Mapper가 붙어 있는 프록시
        Class<?> mapperIf = findMapperInterface(bean);
        if (mapperIf == null) return bean;

        ProxyFactory pf = new ProxyFactory(bean);
        pf.setInterfaces(mapperIf);                 // 시그니처 유지 → 문제없음
        pf.addAdvice((MethodInterceptor) inv -> {
            try {
                return inv.proceed();
            } catch (RuntimeException e) {
                throw normalize(e);
            }
        });
        return pf.getProxy();
    }

    private RuntimeException normalize(RuntimeException e) {
        Throwable t = e;
        while (t != null) {
            if (t instanceof TooManyResultsException tmre) {
                return new IncorrectResultSizeDataAccessException(
                    "selectOne 결과가 2건 이상", 1, tmre);
            }
            t = t.getCause();
        }
        return e;
    }

    private Class<?> findMapperInterface(Object bean) {
        for (Class<?> ifc : AopProxyUtils.proxiedUserInterfaces(bean)) {
            if (ifc.isAnnotationPresent(Mapper.class)) return ifc;
        }
        return null;
    }
}
```

## 예외번역기 교체

```
public class LegacyMyBatisExceptionTranslator extends MyBatisExceptionTranslator {

    public LegacyMyBatisExceptionTranslator(DataSource dataSource) {
        super(dataSource, true);
    }

    @Override
    public DataAccessException translateExceptionIfPossible(RuntimeException e) {
        // MyBatis가 PersistenceException으로 감싸기 전/후 모두 커버
        Throwable t = (e instanceof PersistenceException && e.getCause() != null)
                    ? e.getCause() : e;
        if (t instanceof TooManyResultsException tmre) {
            return new IncorrectResultSizeDataAccessException(
                "selectOne 결과가 2건 이상 반환됨", 1, tmre);
        }
        return super.translateExceptionIfPossible(e);   // SQLException 계열은 기존 번역
    }
}
```

```
@Configuration
public class MyBatisConfig {
    @Bean
    public SqlSessionTemplate sqlSessionTemplate(SqlSessionFactory factory,
                                                 DataSource dataSource) {
        return new SqlSessionTemplate(
            factory,
            factory.getConfiguration().getDefaultExecutorType(),
            new LegacyMyBatisExceptionTranslator(dataSource));
    }
}
```

이렇게 하면, 스프링 db예외 추상화에 벗어난 TooManyResultException을 표준으로 바꿀 수 있다.
여기서 이와 비슷하게 표준에 벗어난것이 있다면, 상황에 맞게 가감하면 될 것 같다.
