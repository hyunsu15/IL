# 간단히 한 일은 docs/한일/YYYY-MM-DD.md 에 남기기
수정이 완료되면 작업 내역을 기록한다.

경로:
docs/한일/YYYY-MM-DD.md

규칙:
- 사용자의 현재 날짜를 사용한다. 이 날짜는 세션이 시작한 날이 아니라 사용자 시간이다. 이를 작성하기 전에 확인한다.
- 파일이 없으면 생성한다.
- 파일이 있으면 맨 아래에 이어서 작성한다.
- 코드 전체를 붙여넣지 않는다.
- 변경 이유와 결과를 중심으로 작성한다.
- 항목당 1~3줄 이내로 작성한다.
- 외부 API 변경 여부를 반드시 기록한다.


# 테스트 코드 작성한다.

내용은 테스트가이드.md를 참고한다.

# 코드 수정 시 영향도 분석 및 연관 로직 안내한다.
- 수정한 함수를 사용하는 컴포넌트를 확인하여, 컴파일나 로직상 문제가 되지 않는지 확인한다.
- 데이터 구조(DTO, Entity 등) 변경 시, 이를 참조하는 매핑 로직이나 API 컨트롤러도 함께 변경 대상인지 확인한다.
