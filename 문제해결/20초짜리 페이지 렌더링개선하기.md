# 20초를 개선하자.
ai가 만든 것을 ai로 개선한 경험.



## 문제점
구글 무료 ai가 만들었던 설계(레게시)에서 대량 건 일때 문제가 있었다.
한 100건 아래 일떄는 준수한 응답속도를 보였다. 하지만 대략 1천건 * 6개 * JSON비교 최악일때 8천줄 정도 되는 순간 특정 페이지가 렌더링이 엄청느렸다.
내가 프론트엔드를 성능 개선 작업을 잘 모르기에, 최대한 ai를 활용해서 개선 할려고 한다.

### 성능측정으로 진짜 문제 찾기
하지만 이것은 단순 추정이라 ai에게 크롬 퍼포먼트 탭 관련 내용을 학습했다.
그래서 목데이터를 통해서 문제 상황과 비슷한 데이터 크기를 만들어달라고 했다. 이것은 가능하면 안하지 않고, 운영에서 문제 되는 부분을 중심으로 관련 프로파일링을 할려고 했었다. 하지만 내부망은 유독 자주 프로파일링이 고장나서 제대로된 피드백을 받지 못했다. 그래서 목데이터를 통해 문제를 재연했다.

그래서 다음과 같은 문제들이 시간을 매우 잡아먹고 있었고, 아래 문제들은 개선하면서 나왔던 문제들이다.
- composition failed background-color
- composition failed background-left-color,background-xxx-color
주된 원인은 사용하고 있던 라이브러이에는 관련 css에 적용할수 없는데 강제로 적용할려다보니, 렌더자체가 오래 걸리는 식으로 판단했다.

## 순수 라이브러리의 다크모드,라이트 모드 쓰기
라이브러리에서 제공하는 순수 다크모드,라이트모드를 사용하기로 결정하고, ai 한테 관련 작업을 시켰다.

## 결과
최악일때 20s가 걸렸던 요청은 최악일떄 2s로 개선되었고 평균은 40ms로 되었다.
단순 css 개선으로 이정도로 극적으로 차이나는 줄은 생각지도 못했다.
이 이상 개선할 수 있는 요소들도 존재하지만, 라이브러리 교체하여, 가상화를 진행해야 한다. 전체 스크롤이 아닌 부분 스크롤 형식으로 들어가져서 사용자 측면으로 좋지 않다고 판단했다.
