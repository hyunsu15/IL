 # 문제 해결에서 중요한 요소

문제 해결은 단순히 해결책을 만드는 과정이 아니다.
가장 중요한 것은 **무엇이 문제인지 정확하게 정의하는 것**이다.

---

## 1. 문제를 정확하게 정의하기

많은 문제는 기술력이 부족해서 해결되지 않는 것이 아니라, 문제 자체를 잘못 이해해서 해결되지 않는다.

### 예시

#### ❌ 잘못된 문제 정의

> 서비스가 느리다.

#### ✅ 올바른 문제 정의

> 특정 API가 DB Connection Pool 대기로 인해 평균 3초 지연된다.

---

#### ❌ 잘못된 문제 정의

> 사용자가 불편해한다.

#### ✅ 올바른 문제 정의

> 파일 업로드 과정이 5단계이며, 해당 단계에서 이탈률이 40% 발생한다.

---

문제가 구체적으로 정의되면 해결 방법은 자연스럽게 보이는 경우가 많다.

---

## 2. 원인과 증상을 구분하기

실무에서 가장 중요한 역량 중 하나는 **증상(Symptom)** 과 **원인(Cause)** 을 구분하는 것이다.

### 예시

| 증상           | 원인                    |
| ------------ | --------------------- |
| CPU 사용률 100% | 무한 루프                 |
| 토큰 무한 재발급    | 인터셉터 조건문 오류           |
| 파일이 섞여 저장됨   | 동일 파일명 사용 + 동시성 처리 미흡 |
| 응답 속도 저하     | DB 쿼리 병목              |

증상을 해결하려고 하면 문제가 반복된다.

원인을 해결해야 문제를 근본적으로 제거할 수 있다.

---

## 3. 문제 해결 과정

### 1) 문제 정의

* 무엇이 문제인가?
* 어디서 발생하는가?
* 재현 가능한가?

### 2) 원인 분석

* 로그 확인
* 메트릭 확인
* 디버깅 수행
* "왜?"를 반복적으로 질문

### 3) 가설 수립

예시:

> 응답이 느린 이유는 DB Connection Pool 부족 때문일 것이다.

검증 가능한 형태로 가설을 세운다.

### 4) 작은 실험

대규모 수정 전에 최소한의 변경으로 검증한다.

예시:

* Pool Size 증가
* 인덱스 추가
* 캐시 적용

### 5) 결과 검증

* 문제가 해결되었는가?
* 성능이 개선되었는가?
* 새로운 문제가 발생하지 않았는가?

### 6) 사람이 읽기 편한가?
- 최대한 간결하게 작성한다.
- 문장이 쓸데 없이 길게 하지 않는다.
