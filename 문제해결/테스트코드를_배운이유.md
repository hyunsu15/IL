## 요약

- 수동 테스트에 드는 시간이 너무 길었다.
- 이를 개선하려고 테스트 코드 작성법을 학습했다.
- 적용해 보니 테스트 시간이 대폭 줄었다.

## 테스트가 너무 오래 걸린다

테스트 코드를 배우기 전에는 UI를 직접 눌러 가며 수동으로 테스트했다. 기본 기능을 UI로 테스트해 보니 단점이 너무 많았다.

- **시간이 오래 걸린다.**
- **화면이 늘어나면 테스트 시간도 곱절이 된다.** 시간 복잡도처럼, 화면이나 버튼 수가 늘면 테스트 시간이 급격히 증가한다.
- **일회성이다.** 다시 테스트하려면 처음부터 UI를 다시 눌러야 한다.
- **통과 여부를 따로 기록해야 한다.** 어떤 테스트가 통과했는지 일일이 적으며 진행해야 한다.

이런 단점이 너무 불편해서 개선하고 싶었다.

## 얻은 장점

테스트 코드 작성법을 학습하니 다음 장점을 얻을 수 있었다.

- **피드백이 훨씬 빠르다.** UI 테스트는 특정 기능에 선행 조건이 필요하면 그 과정까지 일일이 눌러야 한다. 코드로 하면 그 과정을 생략하거나, 손보다 빠르게 테스트할 수 있다.
- **반복해서 쓸 수 있다.** 코드로 남아 있어 실행 버튼만 누르면 빠르게 다시 테스트된다.
- **통과 여부를 자동으로 기록해 준다.** 결과를 보여주므로 따로 적을 필요가 없다.

이렇게 얻은 장점이 많았고, 테스트에 걸리는 시간을 크게 줄일 수 있었다.
