# 2015 — Type 1 / Type 2 결정

> 한 줄: **되돌릴 수 있는 결정을 되돌릴 수 없는 것처럼 다루지 마라.**

## 문 비유

| | 성격 | 방식 |
|---|---|---|
| **Type 1** | 한 방향 문. 들어가면 뒤에서 잠긴다 | 신중하게, 협의해서, 천천히 |
| **Type 2** | 그냥 문. 아니다 싶으면 나오면 된다 | 판단력 있는 개인·소그룹이 빠르게 |

## 진짜 문제

**조직이 커지면 Type 2까지 Type 1처럼 다루기 시작한다.**

무거운 프로세스가 원래는 Type 1을 위해 만들어졌는데, 그게 전부에 적용된다.
그 결과 느려지고, 위험을 피하고, 실험을 안 하게 된다.

그리고 서한에서 **"실패와 발명은 쌍둥이"**라고 쓴다.
발명하려면 실험해야 하고, 실험은 대부분 실패하기 때문이다.
실패를 못 견디는 조직은 발명도 못 한다.

## 예시

| 일 | 유형 | 왜 |
|---|---|---|
| 옷 입어보기 | Type 2 | 벗으면 됨 |
| **머리 자르기** | **Type 1** | 다시 못 붙임 |
| 로그 포맷 바꾸기 | Type 2 | 되돌리면 끝 |
| 라이브러리 버전 올리기 | Type 2 | 내리면 됨 |
| **DB 컬럼 삭제** | **Type 1** | 데이터가 사라짐. 백업 꺼내도 그 사이 건 못 살림 |
| **외부에 API 공개** | **Type 1** | 남들이 이미 쓰기 시작함 |
| 새 툴 한 달 써보기 | Type 2 | 안 맞으면 끊으면 됨 |
| **퇴사** | **Type 1** | 돌아가기 어려움 |

## 함정: Type 2를 Type 1로 만들어버리는 것

"일단 시범으로 해보겠습니다"라고 해놓고 **전사 공지를 때리면**,
되돌릴 때 체면 문제가 생겨서 못 되돌린다. Type 2였던 게 Type 1이 된다.

**작게 시작하면 Type 2로 남는다. 크게 벌이면 Type 1이 된다.**

## 실무 적용 — 브랜치 전략 보고서

이 프레임을 제안서에 넣으면 결재가 훨씬 쉬워진다.

| 결정 | 유형 | 그래서 |
|---|---|---|
| 태그 기반 배포로 전환 | **Type 2** | 논의 짧게, 그냥 해보기 |
| test 브랜치 제거 | **Type 2** | 다시 만들면 됨 |
| 브랜치 구조 전면 개편 | Type 1에 가까움 | 신중하게 |

**"되돌릴 수 있으니 일단 해보고 아니면 원복하겠습니다"**는 반대하기 어려운 제안이다.
리스크를 먼저 계량해서 보여주는 것이기 때문이다.
