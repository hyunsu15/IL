# AI로 개발하면서 느낀 점

## 가이드를 잘 줘야 한다.

가이드 없이 하면 정말 자기 맘대로 만든다. 컨트롤러, 서비스, 레포도 그냥 대충 한다.
REST API를 가이드 없이 만들었더니 그냥 자기 맘대로 URL을 만들었다.
가이드를 주면 그나마 맞춰서 잘해준다.
룰을 정확하게 안내하면 빠르고 원하는 방식대로 개발 가능해 보였다.

## 그래도 문화 충격 먹었다.

프로토타입을 정말 빠르게 만든다. 처음 코파일럿을 썼을 때 놀라웠고, 코덱스를 썼을 때 한 번 더 문화 충격이었다.

## 생산성이 말이 안 되고 효율도 좋다. 기업들이 주니어 안 뽑는 이유를 알겠다.

아무래도 병렬로 작업할 수 있고 코드 품질도 어느 정도 나오는 입장에서, 안 쓸 이유가 없는 것 같다. 클로드 맥스가 지금 환율이 역대급 고점이라고 해도 30만 원($200)이다.
프로덕트를 만드는 속도가 말이 안 된다. 우선 당연히 내가 하는 것보다 훨씬 빠르다. 그리고 제미나이 무료버전 기준으로도, 밤 10시까지 야근을 3~4일은 해야 끝날 것으로 추정되던 일이 근무 시간 안에 끝났다. (제미나이 무료버전은 신뢰성이 낮아서 병렬로 돌리면 과부하가 너무 심해 못 함.)
여기에 내 야간수당과 아끼는 시간까지 계산하면, 회사 입장에서도 매우 가성비가 좋아 보인다.

한편으로는 기업들이 주니어를 안 뽑는 이유를 알 것 같았다. 주니어 고용 비용보다 클로드 맥스 여러 개가 훨씬 싸게 먹힌다고 느꼈다. 내가 기업이라도 주니어 한 명 고용하는 것보다 차라리 클로드 맥스 계정이나 코덱스 계정을 여러 개 돌리는 게 훨씬 효율적이라고 느껴졌다.

## 아직까진 성능개선 명령시 누락된 케이스가 있다.
현재까지 누락되는 경우가 있었다. 내가 작성했던 것에는 리스트인경우는 어떻게 처리하고, 그냥 객체일떄는 이렇게 처리한다. 라는 로직을 그냥 객체일때는 이렇게 처리한다 라고만 고친 적이 있다. 코드길이가 길었고, 복잡한 편 이었지만 누락된 케이스가 있어서 완전 맹신해서 쓰긴 아직 멀었다고 생각한다.

문제가 또 생겼었다. 이번 사례는 데이터베이스에 json를 그대로 저장하는 것인데, json String으로 저장하게 코드를 만들었다. 그러다보니 기능이 미묘하게 다르게 동작하는 코드가 만들어졌다.

아직 ai에게 성능개선은 위험하며, 테스트 코드와 테스트 환경이 있어야 안전해보인다.


## 결국 문제를 찾는 것은 사람이다.

문제를 찾는 건 아직 상당히 부족하다. 문제를 찾아서 주거나, 해결 방향을 제안한다면 확실히 잘 고친다. 하지만 문제부터 찾아서 해결하라고 한다면  엉뚱하게 문제를 해결하는 경우가 있는 것같다. 
예는 페이징 랜더링 개선때 느꼈다. 이때 AI는 가상화 스크롤해서 최적화하라고 제안한다. 여러세션과 다른 AI들도 비슷하게 답을 했다. 하지만 정말 문제였던것은 단순 CSS 문제였고, 이 문제점을 제시하니 AI가 잘 해결주었다. 아직까진 내가 해결하고 싶은 문제를 찾는 것은 불안정하다. 어느정도 갈피를 잘 잡아준다면, 상당히 좋은 도구이다. 

위애서 언급했던 json String 문제도 자체로 문제가 있는지 확인하라고 할때는 정상적으로 작동한다고 말했었다. 하지만 내가 해당 문제를 구체적으로 언급했을 때 그제서야 문제 해결을 해주었다.


## 여유가 생기니, 다른 부가적인 요소들도 더 신경쓰는 것같다.

이전이었으면 코드 개발에 급급해서, 백업시스템같은 요소도 만들지 못할 거다. 그리고 확실히 알아보는 과정도 편하니, 물어봐서 조금만 커스텀하면 될 정도이다. 이전이었다면, 이것을 조사하는 것도 리소스라 시도조차 안했을 것 같다.

그래서 현 시스템에는 환경상 완전 자동화는 아니지만, update, rollback 등 스크립트를 만들어서 더욱 안전하게 운영하고 있다. 이전보다 배포가 훨씬 편하게 개선했다.


그리고 내가 좀더 놓칠수 있는 요소들도 ai가 말해줄 수 있는 가능성도 있기에 확실히 쓸수 있는 환경이라면 쓰는 것이 무조건 낫다.


## AI별 성능 체감

현재까지 써본 것 중에는 코덱스가 제일 좋지만, 한도가 작다.

### Gemini 무료버전
최신 flash버전도 마이바티스 tooManyResultException이 안나오고, InCorrectResultException이 나온다고 함. 다른 gpt나 클로드는 제대로 말해준 반면, 애는 아직 많이 부족해보인다. 뭔가 이걸로 신뢰도가 많이 꺠진 느낌이다.

- 잔 버그들이 꽤 있다. 실행 중에 죽거나, 답변 안 하고 죽음.
- 한 번에 많은 것을 시킬 수 없고, 은근히 구체적으로 말해줘야 한다.
- 컨텍스트를 여러 파일로 줄 시 답변 속도가 곱절로 느려진다.
- 문서로 가르칠 수 없다. 그래서 자기 멋대로 답하는 느낌이라 항상 긴장해야 한다. 어쩔 때는 내 말 들어줄 때도 있긴 함.
- 한도가 무제한인 게 장점. 덕분에 프로젝트를 단기간에 만든 느낌.
- 하지만 이 레거시로 고생하기도 해서 장단이 있어보임.


### 코파일럿 무료버전

생각보다 별로였음. 버그도 잘 못 잡는 모습을 봄. 차라리 Gemini 쓰는 게 나은 듯.

### 코덱스 무료버전

코덱스 무료버전 사용해봤음. 문화 충격 먹음. Gemini 무료버전이나 코파일럿 무료버전을 쓰면서 1차 충격이었는데, 코덱스는 체급이 다름.

대충 말해도 내 말귀를 알아먹는 느낌을 많이 받았고, 문제 해결도 잘하는 편.

아쉬운 점은 사용량. 많이 사용 못 하는 게 아쉬움.

### 클로드

회사에서 사용량을 할당해준 아이디를 써봄. 확실히 좋음. 개인적으로 코덱스가 좀 더 좋게 쓴 느낌임.
코덱스와 유사하게 내 말귀를 알아먹으려고 하고, 문서로도 내 말을 기록할 수 있음.

장점은 병렬로 돌릴 수 있다는 것. 보통 사람이 a, b, c 작업을 한다면 a→b→c 이런 식으로 하거나, a 조금 → b 조금 → a 조금 이런 식으로 작업할 것이다. 하지만 이건 내가 판단만 하고 시키기만 하니 a, b, c를 한꺼번에 병렬로 돌릴 수 있다. 이건 코덱스도 같은 장점일 것 같다. 사람이 계획을 잘 세우고 컨트롤할 자신이 있다면, 엄청난 효율이며 장점이라고 생각한다.

그래도 문서를 통해서 행동을 제한할 수 있음. 제미나이는 진짜 불안하지만 클로드는 조금 믿을 만했다. 문서로 어느 정도 제한하면 그래도 지키려고 노력한 느낌을 받는다.

근데 얘도 살짝 자기 멋대로인 측면이 있음. 띄어쓰기 3줄 이상 하지 말라니까 최대 6개까지 한 것도 있었음.

버그 찾기/수정은 결국 사람이 해야 한다. "기능에 버그가 났다" 이렇게만 하면 가끔은 버그를 아예 못 잡는다. OPUS 최대버전으로 해봤지만 토큰만 낭비했다. "어떤 예시에서 버그가 났다" 이렇게 하면 확실히 더 나은 것 같다. 사내망 작업이라 특정 정보는 반출하지 못하기에, 이런 건 사람이 해야 하는 부분인 것 같다.
